# sparks 数据库五张表结构与业务含义对照说明

## 1. 总体对应关系

经实际查询，`sparks` 数据库中的五张表与语雀文档“数据库转发”中的五类业务表基本一致，字段结构也基本匹配。数据库当前采用的是“一个采集点一行”的长表存储方式。

| 实际表名 | 文档对应表 | 当前数据情况 | 业务用途 |
|---|---|---:|---|
| `device_data_save` | 数据存储表 | 2,654,335 行 | 保存完整传感器历史数据 |
| `device_data_update` | 数据更新表 | 53 行 | 保存各传感器的最新值 |
| `device_data_set` | 数据下发表 | 0 行 | 保存控制指令及下发结果 |
| `device_attribute` | 设备属性表 | 55,573 行 | 保存 PLC 通信和在线状态 |
| `gateway_attribute` | 网关属性表 | 83,042 行 | 保存网关通信、定位等属性 |

五张表之间主要通过以下字段关联：

- `gatewayMac`：关联同一个物联网网关；
- `deviceId`：关联同一个设备，当前主要为 `PLC`；
- `pointId`：关联同一个传感器或数据点；
- `created_at`、`updated_at`：确定数据产生或更新的时间。

## 2. `device_data_save`：传感器历史数据表

该表对应文档中的“数据存储表”，是时序预测最主要的数据来源。

当前数据范围：

- 数据量：2,654,335 行；
- 开始时间：2026-07-23 10:58:08；
- 结束时间：2026-08-11 22:36:34。

同一时间存在多个不同的 `pointId`，说明当前采用文档中的“表模型 1”，即每个传感器数据点单独保存一行。

| 字段 | 业务含义 |
|---|---|
| `id` | 每条历史记录的自增主键 |
| `created_at` | 传感器数据采集时间 |
| `gatewayMac` | 采集该数据的网关唯一标识 |
| `deviceId` | 设备标识，当前示例为 PLC |
| `pointId` | 传感器或数据点的唯一标识，如 `CO2-N1` |
| `pointName` | 传感器中文名称，如“二氧化碳北1” |
| `value` | 传感器采集值，目前以字符串形式存储 |

示例数据说明：

- `CO2-N1`：二氧化碳北1，示例值为 422；
- `LIG-N1`：光照北1，示例值为 881；
- `LIG-N`：光照北，示例值为 682；
- `LIG-S`：光照南，示例值为 3269；
- `HUM-N1`：湿度北1，示例值为 78.5。

与文档相比，实际表增加了 `pointName` 字段，能够直接保存传感器中文名称，便于 Web 展示。`value` 为 `varchar` 类型，模型使用前需要转换为数值类型。

## 3. `device_data_update`：传感器最新值表

该表对应文档中的“数据更新表”，用于保存每个数据点的最新状态。

目前共有 53 行，说明系统中大约配置了 53 个传感器或设备数据点。它不保存完整时间序列，不适合作为模型训练数据，但适合 Web 页面展示当前值。

| 字段 | 业务含义 |
|---|---|
| `id` | 数据点记录的自增主键 |
| `created_at` | 该数据点记录首次创建时间 |
| `updated_at` | 该数据点最近一次更新时间 |
| `gatewayMac` | 网关唯一标识 |
| `deviceId` | 设备标识 |
| `pointId` | 传感器或数据点唯一标识 |
| `pointName` | 传感器中文名称 |
| `value` | 当前或最近一次保存的数据值 |

实际结构比文档多了：

- `updated_at`：便于判断当前值是否长时间未更新；
- `pointName`：便于直接展示传感器名称。

样例中的多个 `value` 为 0，只能说明表内保存的当前值为 0，不能据此认定该传感器的历史数据全部为 0。是否异常应结合 `updated_at` 和 `device_data_save` 的历史记录判断。

## 4. `device_data_set`：设备数据下发表

该表对应文档中的“数据下发表”，用于向 PLC 或传感器下发控制参数，并记录指令执行结果。

当前表中没有数据，说明目前尚未通过该数据库下发控制指令，或者下发功能尚未启用。

| 字段 | 业务含义 |
|---|---|
| `id` | 下发任务的自增主键 |
| `created_at` | 指令创建时间 |
| `updated_at` | 指令状态更新时间 |
| `gatewayMac` | 目标网关标识 |
| `deviceId` | 目标设备标识 |
| `pointId` | 需要控制的数据点标识 |
| `dataType` | 下发值的数据类型，如字符串、布尔值或数值 |
| `value` | 需要下发的值 |
| `isSet` | 是否已经执行下发，通常 0 为未下发、1 为已下发 |
| `success` | 下发是否成功，通常 0 为失败、1 为成功 |
| `message` | 下发失败时的原因或执行信息 |

该表主要服务于设备控制，不参与热环境时序模型训练。

## 5. `device_attribute`：设备通信属性表

该表对应文档中的“设备属性表”，用于记录 PLC 与网关之间的通信状态。

当前数据范围：

- 数据量：55,573 行；
- 时间范围：2026-07-23 10:58:05 至 2026-08-11 22:36:29。

| 字段 | 业务含义 |
|---|---|
| `id` | 设备状态记录的自增主键 |
| `created_at` | 本次设备状态记录时间 |
| `gatewayMac` | 所属网关唯一标识 |
| `deviceId` | 设备标识，当前为 PLC |
| `lastCommRTC` | 网关与设备最近一次成功通信时间 |
| `commTotalCnt` | 网关与设备累计通信次数 |
| `commFailCnt` | 累计通信失败次数 |
| `lossRate` | 通信丢包率 |
| `isOnline` | 设备是否在线，0 为离线、1 为在线 |
| `code` | 网关与设备通信错误码 |
| `message` | 通信失败原因或状态说明 |

样例中：

- `isOnline=1`；
- `commFailCnt=0`；
- `lossRate=0`；
- `code=0`。

说明样例时段内 PLC 在线且通信正常。

该表一般不作为模型输入，但可以用于辅助判断历史数据缺失是否由设备离线或通信故障造成。实际表中 `commTotalCnt` 为 `bigint`，比文档中描述的字符串类型更加合理。

## 6. `gateway_attribute`：网关属性表

该表对应文档中的“网关属性表”，用于记录物联网网关自身状态。

当前数据范围：

- 数据量：83,042 行；
- 时间范围：2026-07-23 10:58:25 至 2026-08-11 22:36:50。

| 字段 | 业务含义 |
|---|---|
| `id` | 网关状态记录的自增主键 |
| `created_at` | 网关属性记录时间 |
| `gatewayMac` | 网关唯一标识 |
| `simInsert` | SIM 卡是否插入，0 为未插入、1 为已插入 |
| `iccid` | SIM 卡唯一编号 |
| `csq` | 4G 通信信号强度 |
| `latitude` | 网关所在位置的纬度 |
| `longitude` | 网关所在位置的经度 |

样例中：

- `simInsert=0`；
- `csq=-1`；
- 经纬度均为 0；
- `iccid` 为空。

说明当前网关可能没有使用 SIM 卡和定位功能，或者这些参数尚未配置。该表目前不适合作为热环境预测模型的输入。

## 7. 对时序预测任务的结论

本次“热环境到热环境”预测应采用 `device_data_save` 作为历史数据来源。其中：

- `created_at` 作为时间索引；
- `pointId` 作为稳定的传感器标识；
- `pointName` 用于中文展示；
- `value` 转换为数值后作为模型变量；
- `gatewayMac` 和 `deviceId` 用于区分数据来源。

`device_data_update` 适合展示实时值，`device_attribute` 可辅助判断设备是否离线，另外两张表暂时不参与预测。

此外，当前数据库只保存了 2026 年 7 月 23 日以后的数据，不包含任务中提到的 2026 年 2 月冬季数据，因此冬季训练数据仍需从 yjy 系统单独导出。
