# 环境时序预测 · 实时部署对接说明

---

## 1. 总体概览

| 项 | 值 |
|---|---|
| 历史数据来源表 | `device_data_save`（长表，一采集点一行） |
| 预测结果写入表 | `device_forecast_save`（**新增表**） |
| 模型 | XLinear（`models/XLinear_s0.pt`） |
| 输入窗口 | 288 行 × 27 特征（连续 5 分钟一行 = 24 小时） |
| 预测输出 | 72 步 × 27 变量 = **1944 行**长表（未来 6 小时，每 5 分钟一个点） |
| 数据粒度 | 5 分钟（原始秒级数据向下取整聚合） |
| 执行频率 | 建议每 5 分钟执行一次（`run_pipeline.py --loop`） |

整体流程：`device_data_save` → 读库转宽表（load_wide_history）→ 纯预测函数（predict_environment）→ 写 `device_forecast_save`（save_forecast_result）。

---

## 2. 预测结果表 `device_forecast_save`（建表）

> 表名常量：`FORECAST_TABLE = "device_forecast_save"`（见 `db_config.py`）
> 建表幂等：`init_forecast_table(engine)`，已存在则跳过。

### 2.1 建表 SQL（等价于代码中 `CREATE_TABLE_SQL`）

```sql
CREATE TABLE IF NOT EXISTS device_forecast_save (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    batch_id        VARCHAR(64)   NOT NULL,
    forecast_time   DATETIME      NOT NULL COMMENT '模型执行时间',
    input_end_time  DATETIME      NOT NULL COMMENT '输入最后时刻',
    target_time     DATETIME      NOT NULL COMMENT '预测目标时刻',
    horizon_step    INT           NOT NULL COMMENT '预测步长 1-72',
    gateway_mac     VARCHAR(64)   DEFAULT '' COMMENT '网关标识',
    device_id       VARCHAR(64)   DEFAULT '' COMMENT '设备标识',
    point_id        VARCHAR(64)   NOT NULL COMMENT '传感器编码',
    point_name      VARCHAR(128)  DEFAULT '' COMMENT '传感器中文名',
    predicted_value DOUBLE        NOT NULL COMMENT '预测值(物理单位)',
    model_name      VARCHAR(64)   DEFAULT '' COMMENT '模型名',
    model_version   VARCHAR(64)   DEFAULT '' COMMENT '模型版本',
    created_at      TIMESTAMP     DEFAULT CURRENT_TIMESTAMP COMMENT '写入时间',
    UNIQUE KEY uk_batch_target_point (batch_id, target_time, point_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='环境时序预测结果表';
```

### 2.2 字段说明

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | BIGINT | 自增 | 主键 |
| `batch_id` | VARCHAR(64) | ✅ | 一次预测批次号（UUID hex，32 位）；同批 1944 行相同 |
| `forecast_time` | DATETIME | ✅ | 本次模型执行时间 |
| `input_end_time` | DATETIME | ✅ | 模型输入最后一行的时刻（预测起点，这批数据是截至到哪里开始预测的） |
| `target_time` | DATETIME | ✅ | 该行预测值对应的未来时刻 |
| `horizon_step` | INT | ✅ | 预测步长，1~72（1 = input_end_time 后 5 分钟） |
| `gateway_mac` | VARCHAR(64) | 默认'' | 网关标识，原样取自来源数据 |
| `device_id` | VARCHAR(64) | 默认'' | 设备标识，当前为 `PLC` |
| `point_id` | VARCHAR(64) | ✅ | 传感器编码，如 `TEM-N`、`CO2-N1` |
| `point_name` | VARCHAR(128) | 默认'' | 传感器中文名，如 `温度北` |
| `predicted_value` | DOUBLE | ✅ | 预测值（逆标准化后物理单位，已做物理范围裁剪） |
| `model_name` | VARCHAR(64) | 默认'' | 固定 `XLinear` |
| `model_version` | VARCHAR(64) | 默认'' | 固定 `xlinear_s0_final_v1` |
| `created_at` | TIMESTAMP | 默认 | 写入时间（数据库自动） |

### 2.3 写入规则（幂等）

- 同一 `batch_id` 重复写入时，先 `DELETE WHERE batch_id = :b` 再插入（避免唯一键冲突）。
- 唯一约束：`(batch_id, target_time, point_id)`，同一批次内不会重复。
- 写入 API：`save_forecast_result(engine, forecast_df) -> int`（返回写入行数，正常为 1944）。
- 兼容两种输入列名：predict.py 输出的驼峰列（自动映射）或已是下划线列名。

## 3. 与 `device_data_save` 的关联

### 3.1 来源表结构（现状）

`device_data_save` 为长表（一采集点一行），关键字段：

| 字段 | 说明 |
|---|---|
| `created_at` | 采集时间（秒级原始时间） |
| `gatewayMac` | 网关标识（当前 `4529ecf8d0b5`） |
| `deviceId` | 设备标识（当前 `PLC`） |
| `pointId` | 传感器编码，如 `TEM-N` |
| `pointName` | 传感器中文名，如 `温度北` |
| `value` | 采集值，**varchar 字符串**，读取后需转数值 |

### 3.2 读取查询（load_wide_history）

```sql
SELECT created_at, pointId, value
FROM device_data_save
WHERE pointId IN (27 个模型所需 pointId)
  AND created_at >= NOW() - INTERVAL 24 HOUR
  AND gatewayMac = :gw        -- 可选过滤
  AND deviceId   = :dv        -- 可选过滤
```

### 3.3 27 个所需 pointId（= feature_cols.json 中特征的下划线前缀）

`BGT-N1, BGT-N, BGT-S, CO2-N1, CO2-N, CO2-S1, CO2-S, HUM-N1, HUM-N, HUM-S1, LIG-N1, LIG-N, LIG-S1, LIG-S, NH3-S, PM10-N, PM10-S, PM25-N, TEM-N1, TEM-N, TEM-S1, TSP-S1, TSP-S, WIN-N1, WIN-N, WIN-S1, WIN-S`

> 特征列命名规则：`pointId_pointName`，如 `TEM-N_温度北`、`CO2-N1_二氧化碳北1`。预测时用 `_` 切分回 `point_id` / `point_name` 写入结果表。

### 3.4 宽表转换规则（长表 → 288×27 宽表）

1. `value` 转数值（`pd.to_numeric`），无法转换/空值丢弃；
2. `created_at` **向下取整到 5 分钟**（`floor("5min")`）；
3. 同一 `5min + pointId` 多条记录取均值（秒级聚合成 5 分钟）；
4. 透视成宽表：行 = 5 分钟时间戳，列 = 27 个 pointId（列名重命名为特征名）；
5. **补齐连续 5 分钟时间戳**，缺失处理：
   - 连续缺失 ≤ 6 个点（30 分钟）：前向填充 + 线性插值；
   - 连续缺失 > 6 个点（>30 分钟长缺口）：**拒绝预测**（抛异常）；
6. 全 0 行（27 列全为 0，判定设备故障）：**拒绝预测**；
7. 取最新连续 288 行，不足 288 行则报错。

输出宽表格式：`DataFrame[时间, 27 特征列]`，时间严格连续 5 分钟。

## 4. 纯预测函数（predict_environment）

### 4.1 函数签名

```python
from predict import predict_environment

forecast_df = predict_environment(
    history_df,               # 必填：宽表 DataFrame（≥288 行连续5min，含时间列+27特征列）
    gateway_mac="",           # 网关标识，原样写入结果
    device_id="",             # 设备标识，原样写入结果
    time_col=None,            # 时间列名；不传自动识别 时间/created_at/timestamp/time
    forecast_time=None,       # 模型执行时间；不传取当前时间
    batch_id=None,            # 批次号；不传自动生成 UUID
    asset_dir=None,           # 模型资源目录；默认取 predict.py 所在目录
)
```

> 首次调用加载模型（`EnvironmentPredictor`），后续调用复用同一模型对象，可反复调用。

### 4.2 输入要求

| 项 | 要求 |
|---|---|
| 行数 | ≥ 288 行（仅用最新 288 行） |
| 时间列 | `时间 / created_at / timestamp / time` 之一，或 `time_col` 指定 |
| 时间连续性 | 最近 288 行必须严格每 5 分钟一行，不得重复、不得断档 |
| 特征列 | 必须包含 feature_cols.json 全部 **27 个特征**（列名精确匹配） |
| 数值 | 全部可转数值、无 NaN、无 Inf；整行全 0 判定故障拒绝 |

### 4.3 输出格式（长表，1944 行 = 72 步 × 27 变量）

列：

```
batch_id, forecast_time, input_end_time, target_time, horizon_step,
gatewayMac, deviceId, pointId, pointName, predicted_value,
model_name, model_version
```

- `horizon_step`：1~72；
- `target_time`：`input_end_time` 起每 5 分钟一个，共 72 个；
- `predicted_value`：逆标准化后的物理单位，并做物理范围裁剪：
  - 湿度 HUM：`[0, 100]`；
  - 温度 TEM：`[-20, 60]`；
  - 黑球温度 BGT：`[-20, 80]`；
  - 其余（CO2/NH3/PM/LIG/WIN 等）：`≥ 0`。

### 4.4 模型资源文件（asset_dir 下）

```
predict.py            # 纯预测函数（含网络结构定义，与训练一致）
feature_cols.json     # 27 特征列表（顺序必须与训练一致）
scaler.pkl            # 训练阶段 StandardScaler（特征数校验 27）
models/XLinear_s0.pt  # 模型权重（含 state_dict 与 feat_names，加载时校验顺序）
```

## 5. 完整数据流（run_pipeline.py）

```
┌──────────────────────────────────────────────────────────────────┐
│ 第0步  init_forecast_table(engine)     建表（幂等，已存在跳过）      │
├──────────────────────────────────────────────────────────────────┤
│ 第1步  load_wide_history(engine)                                 │
│        SELECT created_at, pointId, value FROM device_data_save    │
│        WHERE pointId IN (27个) AND created_at >= NOW()-24HOUR     │
│          AND gatewayMac=? AND deviceId=?                          │
│        → 转数值 → 5min向下取整 → 同点取均值 → pivot 宽表             │
│        → 补齐连续时间戳 + 插值(≤30min缺口) → 最新288行              │
│        输出: DataFrame[时间, 27特征]                              │
├──────────────────────────────────────────────────────────────────┤
│ 第2步  predict_environment(wide)                                 │
│        宽表 → 标准化 → XLinear(288→72) → 逆标准化 → 物理裁剪         │
│        输出: 1944行长表(12列, 驼峰)                               │
├──────────────────────────────────────────────────────────────────┤
│ 第3步  save_forecast_result(engine, forecast)                    │
│        DELETE batch_id → INSERT device_forecast_save (1944行)     │
└──────────────────────────────────────────────────────────────────┘
```

- 单次执行：`python run_pipeline.py`
- 循环执行（每 5 分钟一次）：`python run_pipeline.py --loop`
- 依赖：`pandas, numpy, torch, sqlalchemy, pymysql`
- 数据库配置见 `db_config.py`（TencentDB MySQL `sparks` 库，密码建议走环境变量 `DB_PASSWORD`）

### 5.1 关键参数（db_config.py）

| 参数 | 默认值 |
|---|---|
| `FORECAST_TABLE` | `device_forecast_save` |
| `GATEWAY_MAC` | `4529ecf8d0b5`（环境变量可覆盖） |
| `DEVICE_ID` | `PLC`（环境变量可覆盖） |
| `HISTORY_HOURS` | 24（读取最近 24 小时原始数据） |

## 6. 注意事项

1. **value 为 varchar**：`device_data_save.value` 是字符串，读库时必须转数值，空值/脏值会被丢弃；
2. **长缺口拒绝预测**：历史数据存在 >30 分钟连续缺失，本次不产预测，需保证采集链路稳定；
3. **全 0 故障行拒绝预测**：27 个点同时为 0 视为设备故障，不做预测；
4. **时间必须严格连续**：预测函数校验最近 288 行 5 分钟连续，不满足会报错；
5. **批号幂等**：同一 `batch_id` 可安全重写（先删后插），建议以「预测启动时间」或 UUID 生成；
